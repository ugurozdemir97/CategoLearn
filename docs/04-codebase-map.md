# Codebase map

## Entry and configuration

| Path | Responsibility |
|---|---|
| `index.js` | Registers the Expo root component |
| `App.js` | Database startup, providers, loading/error states |
| `package.json` | Dependencies and run commands |
| `app.json` | Expo and platform configuration |
| `eas.json` | EAS build settings |
| `README.md` | Public project overview |

## Main directories

### `navigation/`

`StackNavigator.js` defines Home, Folder, Card Detail, Settings, Search, and Trash.

### `screens/`

- `HomeScreen.js`: root folders.
- `FolderScreen.js`: child folders and cards.
- `CardDetailScreen.js`: fields and expandable rich text.
- `SearchScreen.js`: in-memory search and result navigation.
- `DeletedScreen.js`: Trash, restore, and permanent deletion.
- `SettingScreen.js`: sort preferences, theme, language, import, and export.
- `ErrorScreens/`: database loading and startup error screens.

### `database/`

- `db.js`: opens the module-level SQLite connection.
- `schema.js`: creates tables, unique indexes, and restore system items.
- `queries.js`: CRUD, move, copy, deletion, and restore operations.
- `exportDb.js`: database file export/import.

### Shared UI and state

- `context/`: theme, language, sort modes, and the in-memory clipboard.
- `hooks/`: selection, modal state, and custom-order behavior.
- `components/Navigation/`: headers, footer actions, and breadcrumbs.
- `components/Modals/`: create/edit, color, confirmation, and information dialogs.
- `components/Editor/`: rich-text editing and HTML display.
- `components/Buttons/` and `components/Blocks/`: reusable UI pieces.

### Utilities and resources

- `utils/validation.js`: name validation.
- `utils/handleSort.js`: list sorting.
- `utils/handleFooterActions.js`: selection and clipboard actions.
- `utils/formatTime.js`: date display.
- `storage/`: AsyncStorage preference helpers.
- `language/locales/`: English and Turkish strings; update both when adding keys.
- `styles/`: themes and shared styles.
- `assets/`: application icons and splash images.

## Where to start for a change

| Change | Start with |
|---|---|
| Folder/card/field behavior | Relevant screen, `CreateModal.js`, `queries.js` |
| Database schema | `schema.js`, then add an upgrade path for existing databases |
| Copy or move rules | `ClipboardContext.js`, `handleFooterActions.js`, `queries.js` |
| Sorting | `HeaderBar.js`, `handleSort.js`, `useCustomSort.js`, `sortPreference.js` |
| Trash and restore | `DeletedScreen.js`, `queries.js` |
| Search | `SearchScreen.js` |
| Backup | `exportDb.js`, `db.js`, `schema.js` |
| Text | Both locale JSON files |
| Theme | `styles/colors.js` and any hard-coded colors in components |

## Android folder

The local `android/` directory is ignored by Git and appears to be generated by
Expo prebuild. Before making a lasting native change, decide whether it belongs in
Expo configuration or whether the native directory should become a maintained
source. Avoid maintaining the same setting in two places.
